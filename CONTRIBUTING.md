# Contributing Guidelines

Thank you for contributing to our Software Development Course repository! Please follow the guidelines below to keep everything organized and consistent.

---

## Branching Strategy

- Use descriptive branch names based on the type of work:
  - `assignment-<number>` — e.g., `assignment-01`
  - `lab-<number>` — e.g., `lab-03`
  - `project-<name>` — e.g., `project-final`
  - `docs/<topic>` — e.g., `docs/setup-guide`

## Commit Messages

Write clear, concise commit messages in English using the imperative mood:

```
Add solution for Assignment 01
Fix bug in lab-02 exercise
Update README with project structure
```

## Pull Requests

1. Always open a **Pull Request (PR)** before merging into `main`.
2. Assign at least **one teammate** as a reviewer.
3. Include a short description of what was changed and why.
4. Wait for approval before merging.

## File Organization

Place your work in the correct directory:

| Type | Directory |
|------|-----------|
| Assignments | `assignments/` |
| Lab exercises | `labs/` |
| Projects | `projects/` |
| Shared documents | `docs/` |

## Code Style

- Use consistent indentation (spaces or tabs — pick one per project and stick with it).
- Include comments where the logic is not immediately obvious.
- Remove unused code and debug statements before committing.

---

If you have any questions, reach out to your teammates or open an issue.
